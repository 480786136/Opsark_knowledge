# Knowledge 管理前端

单管理员管理页面，开发服务通过 Vite 将 `/api` 转发到本机 `127.0.0.1:8002`。服务间凭据与客户端 Knowledge Key 不进入浏览器配置；管理接口使用同源会话和 CSRF Token。

## 工作概览、归属与批量发布

工作概览使用后台全库汇总，区分可检索文档、待审核草稿和索引中状态；下方知识库列表单独分页。文档列表支持按所属库服务端筛选，显示知识库、来源类型、创建者。创建者来自创建审计或 Core 上传客户端标识，不从当前登录账号推测历史归属；缺失时明确显示未留存。没有引入多人授权或负责人分配。

在“知识文档”筛选目标库，勾选待审核文档后点击“批量发布”。每次最多 100 篇，确认框列出所选标题、库、来源和草稿修订，并要求人工确认逐篇审核。后台逐篇提交，修订冲突、非草稿、停用库等分别返回失败原因；提交成功只代表进入索引队列，Worker 完成后才可检索。过滤或翻页会清空选择，避免误发隐藏文档。

检索页显示所选库的可检索/待审核/索引中数量。未配置 Embedding 属于正常关键词模式，不报向量故障；已配置但调用失败才显示降级提示，HTTP 请求失败单独显示错误。切换查询或知识库清除旧结果；全是草稿时提示先审核发布，而不是建议盲目配置模型。

本次接口新增 `GET /api/admin/v1/knowledge/overview`、`POST /api/admin/v1/knowledge/documents/batch-publish`；文档列表支持 `knowledge_base_id` 参数。前后端需一起更新并重启 API，无新增数据库迁移，Worker 需保持运行。

```sh
npm ci
npm run dev
npm run build
```

浏览器回归测试：

需要按日期保存日志和截图时，从 Knowledge 根目录使用 [统一测试归档入口](../../docs/测试/知识库测试/README.md)。`--suite web` 测试模拟接口页面，`--suite browser` 测试隔离真实 API/Worker。入口通过 `KNOWLEDGE_TEST_OUTPUT_DIR` 指定当轮截图目录；不设该变量时下列原有命令仍使用 `web/test-results/`。

```sh
npx playwright install chromium
npm test
```

测试会启动独立的 `127.0.0.1:5186` 前端，并拦截管理 API。覆盖来源不在收件箱当前页、草稿与发布快照隔离、提炼、版本冲突输入保留、新来源替换确认、管理员引用预览、降级检索提示、文档和来源分别删除、当前发布索引重建。这些测试验证浏览器行为，不代替真实 API、数据库及 Worker 的端到端验收。

真实服务浏览器验收可从 Knowledge 项目根目录运行：

```sh
npm --prefix web run build
.venv/bin/python scripts/smoke_browser.py
```

该脚本创建临时数据库、管理员和来源，启动独立 API 与 Worker，并通过子进程环境传递测试凭据；完成后停止进程。浏览器实际执行登录、来源查看、保留元数据的编辑、发布、检索引用、历史版本查看和下架，并创建两篇测试草稿验证创建者及批量发布完成。截图位于 `web/test-results/live/`；登录过程禁用网络 trace 和录像，避免保存凭据。

若已有隔离服务，可用 `KNOWLEDGE_LIVE_URL`、`KNOWLEDGE_LIVE_USERNAME`、`KNOWLEDGE_LIVE_PASSWORD`、`KNOWLEDGE_LIVE_DOCUMENT_ID` 环境变量调用 `npm run test:live`。仅允许回环地址；指定文档必须是未发布、关联来源的测试草稿。测试会修改并发布该文档，最后下架，另外在同一库新建并发布两篇测试资料。不要指向真实业务库。未配置环境时此测试自动跳过。

文档详情直接加载文档、关联来源、版本历史、提炼对照及索引构建记录。历史版本通过管理员端点读取，对外引用仅由后端授权的当前发布版本提供。任务错误只显示可理解的状态与任务 ID，避免在页面回显底层服务异常中的敏感信息。
