# 知识整理质量 v2

本页说明基于证据的规则整理基础，不执行上传命令、不自动发布。可选 AI 经验提炼现已接入，启用与审核流程见 [AI经验提炼](AI经验提炼.md)；关闭 AI 时仍使用本页规则草稿。

## Core 上传内容

- 当前轮次的阶段尝试与当前计划，最多最近 30 步；失败尝试不会被相同步骤 ID 的重试覆盖。其他轮次和超限部分在结果范围中标明。
- 完整步骤说明、预期验收标准、主命令关键输出、关联独立校验的输出与明确通过/失败标记。
- Core 最终总结以“客户端陈述”标注，不替代执行证据。
- 保留自动凭据过滤和用户预览确认。命令仍是可选项；关键输出与总结默认进入预览，请审核内容后确认。
- 输出先清理终端控制符、脱敏，再压缩重复进度；超长输出保留首尾并标注省略。超过字段上限的命令整体省略，避免半条命令被误用。
- 只有任务已完成、收集的所有步骤具备成功/校验依据且无已知历史遗漏或证据冲突时报告成功。其他情况保留部分完成、失败或未知，不根据总结措辞推断成功。

## Knowledge 整理

草稿包含目标、适用范围、操作步骤、验收标准与校验证据、关键输出、结果边界、审核事项和来源修订。

未提供环境、缺少输出或独立校验时明确标注。预期标准与实际结果分开；来源规则版本为 `core-upload-v2`，草稿整理规则为 `knowledge-draft-v2`。

这不是 AI 泛化经验提炼；不会猜测环境、生成未执行命令或补写成功结论。发布后才进入检索。

## 使用与验收

1. 更新并重新打开 Core。在任务上传预览中核对输出、独立校验和总结；需要命令时勾选“附带执行命令”。
2. 在 Knowledge 根目录重启 Worker：`.venv/bin/python -m knowledge.processing`。本次无数据库迁移或新增环境变量。
3. 重新上传原任务，生成新的来源修订；此前上传记录缺少的输出无法由服务端恢复。
4. 在知识管理的“知识文档”查看新草稿，核对证据与整理规则版本，再审核发布。“记录收件箱 → 查看脱敏来源”仍显示来源 JSON。
5. 在“检索调试”检查新版本内容。旧已发布文档不自动修改或下架；如果同一任务的旧修订仍在检索中，可审核后手动下架旧文档。

建议用仓库拉取任务验收：保留 Git 可用性、目录检查、`FETCH_OK`、origin 和 HEAD 输出，过滤克隆百分比；验证失败或没有校验的任务不能变成无条件成功经验。
