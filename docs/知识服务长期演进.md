# 知识服务长期演进与一期约束

更新：2026-09-23。状态：长期约束与实现进度；本轮以单管理员完整知识流程为范围，不引入用户/空间体系。

独立管理页面、本地管理员、会话/CSRF、来源修订与版本快照、索引代次及后台重建已实现；Admin 知识页面/代理已退役。当前可重复验收结果见 [本机流程验收报告](本机流程验收报告.md)，生产门禁见 [发布验收与运维手册](发布验收与运维手册.md)。

## 保留的基础

保留结构化入库、持久任务、模板草稿、人工审核、版本发布与检索，不从零重写。知识已独立拥有管理入口/鉴权/资料/API；Admin 管模型接入及后续平台业务，旧知识代理已退役。

知识处理可直接配置第三方 API，也可选择 Admin 转发接口，但不能强制依赖 Admin 在线。未配 Embedding 可使用关键词模式。规则整理与可选 AI 提炼已实现，包含证据类型校验、并发修改保护和前后对照；不自动判断自然语言事实为真，不自动合并多任务。

## 索引和数据库

发布指纹与 Worker 当前配置不一致时，在批次前后和落库前阻止发布，标 INDEX_CONFIG_MISMATCH，并保留旧发布版本。已完成独立构建配置快照/代次、当前发布的后台重建与原子激活切换，并验证失败保留旧索引、显式重试恢复。

内容版本与索引代次分开。模型/切片变化可后台重建，验证后原子切换；旧索引按保留策略清理。检索应反映实际通道和索引覆盖，不能仅因查询向量生成成功就声称混合检索完整可用。

旧库须先应用 `0004/0005`，其中向量列已改为不固定维度；之后修改模型/维度需要重建对应索引，无须每次修改数据库列。新索引就绪前旧索引保留，查询配置不匹配时可降级关键词。历史迁移定义已冻结；已有数据库升级仍需备份与恢复方案。

当前约 1800 字符按章节/代码块切片（`sections-v3`），保留引用行号。PostgreSQL 将库/适用性/路径过滤及全文、向量候选检索下推数据库并限制候选规模；SQLite 保留 5 万片段扫描保护阈值。这些上限不是容量保证，实际延迟与召回应以目标语料实测为准。

建立中文运维评测集，覆盖版本差异、精确路径、无答案、权限负例；测命中率、引用正确性、延迟与降级率。是否增加独立向量库由实际规模决定。[pgvector 官方资料](https://github.com/pgvector/pgvector)

## 生命周期、权限与安全

每次上传、管理、检索、引用和删除都校验主体/资源权限；现有 scope/允许库与高权限内部 Token 不等于多租户。未来统一登录不能替代资源授权。

删除文档当前清理其版本/切片，但来源 JSON 仍在；来源需另外删除且保留无正文去重标记。目标：明确操作范围，分别规定来源、草稿、版本、索引、审计、缓存、备份的保留期。备份按政策到期清理，恢复后重放删除标记，不承诺点击删除即抹除全部副本。

旧版本的公共引用在新版本发布后不可读；管理员版本历史通过独立管理接口读取。历史审计访问不重新开放已撤销资料给客户端。

正文目前是数据库明文。Embedding 向上游外发片段，AI 整理可能外发更多资料；启用前确认授权、范围与预算。正则脱敏和人工审核不是完整 DLP。检索结果只能作为非可信参考，不能覆盖 Agent 指令、执行授权或实时检查。[OWASP RAG 安全指南](https://cheatsheetseries.owasp.org/cheatsheets/RAG_Security_Cheat_Sheet.html)

## 知识、记忆、任务状态

| 类型 | 示例 | 管理要求 |
| --- | --- | --- |
| 知识 | 某软件版本的故障处理方法 | 审核、证据、版本、适用范围、授权共享 |
| 记忆 | 用户语言偏好、项目部署约定 | 主体、同意、更正、有效期、冲突和遗忘 |
| 任务状态 | 当前步骤、检查点、审批 | core 任务生命周期，不自动变长期知识 |

可复用底层组件，不共用发布/权限语义。记忆部署归属另行设计，不自动由任务创建画像。

## 次序与验收

单管理员本轮已补齐来源/适用性、版本发布、索引代次、任务监控和恢复流程，保留 Core 公共协议兼容。测试包含 API/Worker 配置不一致、旧索引回退、下架和备份恢复。正式多人使用是另一个范围，需先实现主体/资源隔离。

AI 提炼已实现；真实供应商质量仍需验收。多来源自动合并、文件解析、记忆后续实施；对象存储、共享队列、多副本按实际需求引入。
