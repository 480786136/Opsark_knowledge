# 经验提炼 v2 与向量索引边界

## 当前实现

- 输入先建立带类型的引用字典。旧客户端以 observation 上传的 expected-* 和明确标注“预期验收”的内容归入 expectation。
- 事实只能引用 command_result、validation、observation；预期标准使用“验收要求”；环境、任务结论和命令文本使用“来源声明”。引用不存在或类型不匹配会保留旧草稿并报告失败。
- 类型校验不是自然语言事实证明。仍须审核结论是否被具体输出支持，不保证消除所有幻觉。
- 本次发现、建议、结论边界分区。检测到错误输出抑制或环境缺失时，在正文中保留质量提示。
- 新提炼正文不附加完整原始规则草稿。原始资料继续保存在 source_records.payload，按来源记录及引用 ID 审计。
- Context 新增可选 runtime：os、shell、scope、privilege、visibility，各值最多 200 字。兼容旧上传；这些字段都是客户端声明，不作为服务端实测事实。
- 本次没有修改 Core 自动采集；旧来源无法通过重新提炼补出真实环境。
- 发布按章节边界分块，保留原文行号，超过大小限制的内容仍会分段。分块不是模型生成的摘要。
- 新分块 ID 由分块规则版本、不可变发布版本 ID、序号、正文生成。相同输入重试得到相同 ID。

## 后续 Milvus 接入契约

indexing.vector_entity 是后端无关的数据导出函数；当前没有连接 Milvus，也没有部署向量服务。

SQL 保持文档、版本、来源、权限与发布状态的权威来源。Milvus 仅作为可重建的候选检索索引。
导出包含主键、知识库、文档、发布版本、来源记录、正文 hash、行号、环境、软件、embedding 配置版本及向量。
只有与 SQL 当前发布版本匹配的块才能导出；原始凭据和来源全文不进入导出数据。
历史发布版本仍保留原正文，因此若要消除历史文档中的重复附录，应人工确认后重新整理、发布，不自动改写历史。

实际接入还需实现：

1. 事务 outbox 与幂等 upsert，处理 SQL 提交和远端写入之间的失败；避免在数据库事务内调用远端服务。
2. 以 embedding 模型、维度及配置版本隔离索引；构建完成后切换索引，不混用维度。
3. 候选查询限制授权知识库，返回结果再次回 SQL 核对当前发布版本、库授权和下架状态；远端残留不能绕过权限。
4. 下架/撤销事件、删除重试与重建任务。仅改变向量条目状态不能代替 SQL 授权检查。
5. 向量服务故障时保留现有关键词检索；同步状态、重试、容量与耗时需要监控。

主键与幂等更新设计参考 Milvus 官方 upsert 文档：
https://milvus.io/docs/upsert-entities.md

## 升级与验收

本次没有增加数据库列，不需要新迁移。重启 Knowledge API 与 Worker 后，重新提炼生成 experience-v2 草稿，再人工审核发布。
不会自动重新提炼或改写现有已发布文档，不会修改现有 embedding 配置指纹，历史向量仍按原有规则检索。

回归覆盖：预期与声明冒充事实、来源警告、引用有效性、失败保留草稿、发布审核流程、分块行号、稳定 ID 和非发布版本导出拒绝。
